# Emby Migrator v1.1.6

`v1.1.6` 提升大批量迁移吞吐与稳定性，修复元数据导入静默失败风险，完善优雅退出与默认部署安全。

## 性能

- 导入时 `info.json` 每个条目只读取解析一次，替代原先同一文件的 2~3 次重复读取。
- 单个条目的多张图片改为有界并行下载，结果顺序保持确定。
- 媒体数据库计划回读校验并行化，数千条目时显著缩短耗时。
- SQLite 写入复用预编译语句并一次性规范化字段名，批量写库提速数倍。
- 媒体流去重不再逐条 JSON 序列化；媒体信息集合与字段查找改为一次性构建。
- 任务日志的文件写移出共享锁，避免并发 worker 因磁盘 I/O 相互串行。
- 前端日志渲染由整串重建改为增量 DOM，长任务不再卡顿。

## 正确性与可靠性

- 导出包 `info.json` 损坏或不可读时，对应条目会被标记为失败并记录原因，不再把近乎空的有效载荷写入目标服务器。
- 任务队列增加 panic 防护：单个任务崩溃不再击穿整个进程，状态正确标记为失败。
- 优雅退出：关闭服务时先断开日志流、取消运行中任务并等待收尾，避免 SIGTERM 时进程直接退出导致"已停 Emby 容器未重启"。
- 断点续跑与并发缓存改进：singleflight 的查询上下文与发起者解耦，发起者超时不再拖垮其他等待者。
- 重试退避加入随机抖动，避免高并发下同相重试风暴。

## 安全

- 应用配置、用户配置、Telegram 配置全部改为临时文件 + 原子重命名写入，并增加缓存与读写锁，消除并发保存丢失更新。
- 登录对未知用户名执行等价 bcrypt 计算，抹平用户名枚举的时序侧信道。
- `X-Forwarded-Proto` / `X-Forwarded-For` 仅在显式设置 `EMBY_MIGRATOR_TRUST_PROXY` 时采信，防止客户端伪造代理头。
- docker-compose 默认仅回环端口发布，并提供 `host.docker.internal` 访问宿主机 Emby 的说明。

## 兼容性

- 媒体数据库同系列版本白名单支持 `EMBY_MIGRATOR_DB_VERSIONS` 覆盖，便于声明额外兼容系列；默认仍为 `4.8.11.x` 与 `4.9.5.x`。

## 部署

- Docker 镜像升级到 `alpine:3.22`，并移除 build 阶段多余的 `COPY web`，加速增量构建。

## 验证

- 全量 Go 测试、`go vet`、服务器构建通过。
- 前端 JavaScript 语法检查通过。
- GitHub Actions CI 与 Docker Hub 多架构镜像构建通过。
