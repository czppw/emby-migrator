# Emby Migrator v1.1.7

`v1.1.7` 修复一批从代码复审中发现的数据完整性与并发问题，重点解决媒体技术信息写库计划被静默覆盖导致部分媒体信息永不写库的风险。

## 数据完整性

- 媒体技术信息写库计划改为按目标服务器合并：增量导入或补导不再用新计划覆盖旧计划，之前已计划但本次未处理的条目会被保留，避免大批量媒体信息在写库时被静默丢弃。
- 名称唯一但年份冲突时不再接受唯一匹配：源条目带有年份而目标候选年份不一致（例如同名翻拍片）时，改为标记为歧义，不再把元数据写到错误的条目上。

## 并发与重试

- 重试退避的随机抖动改用并发安全的全局随机源，消除多 worker 并发重试时的数据竞争。
- 修复 `Retry-After` 处理逻辑写反的问题：服务器要求等待更久时，现在正确延长退避并受 30 秒上限约束，不再反向下调。

## 稳定性

- 优雅退出：即使 HTTP 排空超时，也会继续执行任务队列关闭，确保媒体信息写库任务有机会重启目标 Emby 容器。
- Docker 引擎响应头超时由 30 秒提高到 90 秒，覆盖最长 60 秒的容器停服宽限期，避免容器尚未停完就被判定超时、随后重启一个仍在停止中的容器。

## 验证

- 全量 Go 测试、`go vet`、服务器构建通过。
- 新增回归测试覆盖计划合并、年份冲突拒绝匹配与 `Retry-After` 上限。
